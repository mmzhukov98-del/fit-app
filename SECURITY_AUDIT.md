# Аудит безопасности и приватности

*Дата: 13.11.2026 · Ветка: `hardening` · Тип приложения: PWA (HTML/CSS/JS без сборки и без зависимостей)*

Чек-лист OWASP MASVS и iOS-специфика (Keychain, Data Protection, HealthKit, ATS) применимы к нативному приложению. Здесь — веб-приложение, поэтому каждый пункт помечен как **применимо / не применимо**.

## 1. Архитектура данных

| Что | Где хранится | Передаётся по сети |
|---|---|---|
| Профиль, цели, тренировки, питание, вес, замеры, отчёты | `localStorage` браузера на устройстве (ключ `fitapp.data.v1`) | **Нет** |
| Код приложения | GitHub Pages (HTTPS) + кэш Service Worker | только загрузка кода |
| Резервные копии / отчёты / коды дуэли | файлы и текст, которые пользователь сам сохраняет или пересылает | только по действию пользователя |
| Личные файлы настройки (`personal/`) | только на компьютере владельца, в `.gitignore` | **нет**; проверено: `/personal/...` на сайте отдаёт 404 |

Сервера, API, аккаунтов, токенов, аналитики, рекламы, сторонних шрифтов и библиотек — **нет**.

## 2. Результаты проверки

| # | Направление | Статус | Как проверено / комментарий |
|---|---|---|---|
| S1 | Внешние запросы | ✅ проверено | CSP `default-src 'self'; connect-src 'self'; script-src 'self'`; в коде нет `fetch` к внешним адресам; ссылки на видео открываются в новой вкладке с `rel="noopener noreferrer"` |
| S2 | XSS (внедрение HTML/JS) | ✅ проверено | Пользовательские строки выводятся через `esc()`; встроенные скрипты и обработчики заблокированы CSP |
| S3 | Код дуэли от партнёра (недоверенные данные) | ✅ исправлено (P1) | Было: проверялись 2 поля, повреждённый код ломал экран навсегда. Стало: строгая схема (`sanitizeCard`) — даты, диапазоны, белый список полей, длина ≤ 8000; сохранённые коды фильтруются при чтении. 8 негативных тестов пройдены |
| S4 | Импорт резервной копии | ✅ исправлено (P1) | Было: поверхностная проверка. Стало: полная проверка структуры (`validateData`), отказ для копии из более новой версии, страховочный снимок перед заменой и «Вернуть как было». 6 тестов пройдены |
| S5 | Повреждение сохранённых данных | ✅ исправлено (P1) | Было: при ошибке чтения данные молча заменялись пустыми. Стало: копия откладывается (`fitapp.data.corrupt.*`), пользователь предупреждается. Тест пройден |
| S6 | Небезопасная десериализация | ✅ | Только `JSON.parse`, без `eval`/`Function`; объекты из файлов глубоко копируются |
| S7 | Шифрование данных на устройстве | ⚠️ не применимо полностью | `localStorage` не шифруется приложением; защита — блокировка iPhone и шифрование iOS. Keychain/Data Protection для PWA недоступны |
| S8 | Резервные копии | ⚠️ риск принят | Файлы — открытый JSON со сведениями о здоровье. Рекомендация P2: опциональное шифрование паролем (AES-GCM, WebCrypto) |
| S9 | Публичный репозиторий | ⚠️ частично | Мед. данные и анкеты вынесены в `personal/`. В коде остаются обезличенные детали программы (пульс покоя, история бега, адрес магазина для цен) — P2: обобщить |
| S10 | Авторизация, сессии, токены, IDOR, SQLi, API | ➖ не применимо | Нет сервера и аккаунтов |
| S11 | Изоляция двух профилей | ✅ по архитектуре | Каждый профиль — на своём телефоне; обмен — только обезличенные проценты дуэли |
| S12 | Deep links | ✅ | Только внутренние `#/...` маршруты; неизвестный маршрут → главная |
| S13 | Сторонние зависимости / CVE | ✅ | Зависимостей нет |
| S14 | Certificate pinning | ➖ не применимо | Нет собственных сетевых запросов |
| S15 | Apple Health / HealthKit | ➖ не применимо | Интеграции нет; для PWA недоступна |
| S16 | Буфер обмена | ✅ | Чтение — только при вставке кода дуэли по действию пользователя |

## 3. Что не проверено / невозможно проверить здесь
- Поведение хранилища iOS при нехватке места и очистке данных Safari (нужен реальный iPhone).
- Тестирование на проникновение сторонним инструментом не проводилось.
- Отсутствие уязвимостей **не гарантируется** — проверка ручная, по коду и тестам выше.
